# Fork workflow

## Branches

| Branch | Content |
|---|---|
| `main` | Identical to `main` of `https://gitlab.gnome.org/World/fractal`. Never committed to. |
| `phosh` | Default branch: upstream plus `AGENTS.md`, `CLAUDE.md`, `docs/`, `.github/`, the Flatpak manifest and the fork's changes. |

The fork started at upstream commit `9fbc7283` (2026-11-04, version
14.3 in development).

## Upstream sync

`.github/workflows/sync-upstream.yml` runs daily at 02:23 UTC: it pushes
upstream's `main` to the fork's `main` (not forced) and opens a pull
request `main` -> `phosh`. Merge it with a merge commit. Conflicts are
resolved on a branch from `phosh`.

## Small diff

Every line changed in an upstream file can conflict in a later merge.

- Upstream's file names stay (`data/org.gnome.Fractal.*`, icons,
  `build-aux/org.gnome.Fractal.Devel.json`); meson keeps `base_id` for
  them and only `application_id` is `de.nexumia.Nuntius`.
- The project and gettext package stay `fractal`, so translations keep
  working; the binary is still `fractal`.
- Upstream's `AGENTS.md` is replaced by the fork's.
- New features go into new files where possible.

Changed upstream files so far: `meson.build`, the desktop file and the
metainfo template, `src/application.rs` (name, About dialog, UnifiedPush
hooks in `constructed` and `dbus_register`),
`src/main.rs` (also `mod unifiedpush`), `src/login/local_server.rs`, `README.md` (a Nuntius
section on top), `REUSE.toml` (upstream's entry for its `AGENTS.md`,
which it took from GoToSocial under AGPL-3.0-or-later, removed together
with `LICENSES/AGPL-3.0-or-later.txt`; the fork's files get their own
entry).

## No upstream contributions

Fractal's `CONTRIBUTING.md` forbids content generated by large language
models in code, documentation, issues and artwork. Nothing written by an
agent goes upstream: no merge requests, issues or comments. If the
owner wants to ask upstream something, they write it themselves.
